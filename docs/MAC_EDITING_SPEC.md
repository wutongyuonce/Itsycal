# Mac 端新建与编辑日程、提醒事项

本文是 Mac 菜单栏窗口里新建、编辑、删除日程与提醒事项的现行契约。代码与本文冲突时以代码为事实，并同步修正本文。

## 行为

- **新建（`+`、⌘N、双击日期）**：表单顶部可选「日程 / 提醒事项」。
  - 日程：标题、位置、全天、开始/结束、重复、提醒（最多 3 个）、备注、URL、日历，与原先一致。
  - 提醒事项：标题、全天（即不设具体时间）、日期、重复、提醒、备注、URL、列表；没有位置和结束时间。切到提醒事项时若尚未授权，先请求提醒事项权限；拒绝或没有可写列表时提示并回到日程。
- **编辑**：在议程中点开条目的详情弹窗，点铅笔按钮；或右键选「编辑…」。打开同一张表单，预填当前值，不显示类型切换。
  - 重复日程保存时询问「仅此日程 / 所有将来日程」；改了重复频率时不询问，直接作用于整个系列。
  - 选择器表达不了的重复规则（例如每周多天、按次数结束）显示为「自定义」并原样保留；没动过的提醒设置也原样保留，所以选择器不支持的提醒时间不会被丢掉。
  - 只读日历的条目、重复提醒事项的「后续发生」不提供编辑和删除。
- **删除**：详情弹窗的删除按钮、右键「删除…」，日程与提醒事项都可以，删除前确认；重复日程询问只删这一次还是所有将来日程。
- **撤销**：新建、编辑、删除都登记到窗口的撤销栈，⌘Z 撤销、⇧⌘Z 重做。条目已在别处被删除或改动时，撤销只发出提示音。

## 规则与权威位置

| 规则 | 权威位置 |
|---|---|
| 条目能否编辑/删除（日历可写且不是重复提醒的后续发生） | `EventInfo.isEditable` |
| 编辑保存与撤销：先记下旧值，应用修改并保存，撤销时把旧值重新应用到同一条目（重复日程按标识符 + 开始时间找到那一次），重做由撤销自身登记 | `-[EventCenter updateItem:span:changes:undoManager:error:]` |
| 删除与新建提醒的原子提交与撤销 | `-[EventCenter applyBatchChangesWith…]` |
| 表单字段到 EventKit 对象的映射（新建与编辑共用） | `-[EventViewController fillItem:]` |

## 验证

- `Tests/EventCenterCheck.m`：编辑后撤销恢复旧值、重做再次应用。
- 真机：新建日程/提醒、编辑单次与重复日程、编辑提醒、删除日程/提醒后 ⌘Z 恢复、只读日历条目不出现编辑/删除。
